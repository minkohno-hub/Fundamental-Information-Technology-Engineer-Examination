- 進捗報告だけで終わらず、実装→検証→修正→保存まで進める。テスト未実施の項目を検証済みと報告しない。不明点・未検証事項は正直に区別して報告する

## 3. プロダクトの目的と確定要件（削除・緩和禁止）

基本情報技術者試験の全出題範囲を、**問題演習を中心**に学べる、無料・ログイン不要・インストール不要・初回データ取得後はオフライン対応の日本語 Web アプリ。GitHub Pages で公開。

- IPA の**正式に適用されるシラバス Ver.9.2**を網羅（将来の改訂案と混同しない）。科目A（90分・60問・四肢択一）・科目B（100分・20問＝アルゴリズムとプログラミング16＋情報セキュリティ4）の両対応。採点は IRT・各 1000 点満点で 600 点以上。合格可能性や IRT 得点の推定は表示しない
- 問題：品質承認済み（verified）。出典・著作権・ライセンス状態・検証状態・検証ログを管理。IPA 公開問題は教育目的で出典明記・改変明示のうえ利用可。旧午前過去問は利用しない
- 解説：正解の理由、各選択肢の正誤理由、基礎知識、関連知識、略語の英語正式名称・日本語訳・単語分解
- モード：一問一答（5/10/20/50問、分野・ランダム・未回答・苦手・復習・お気に入り・理解度）、標準出題（未回答60%・要復習25%・復習時期15%）、科目B 短時間学習（入力式可）、計算・本格プログラミング専用モード、擬似言語（IPA 別紙2準拠）の実行シミュレーター（ステップ送り/戻し・変数・配列・条件・履歴）、本番形式の模擬試験（科目A 60問90分／科目B 20問100分、本番・練習・短縮・無制限、見直しフラグ、履歴、試験後分析、復習セット）
- 分析（初見/全体/復習時の正答率、分野別、苦手、連続日数、網羅率）、用語辞典、コンパクト参考書、プログラミング講座、全文検索、学習プラン（任意）
- UI：スマホ・PC 最適化、文字サイズ、ライト/ダーク、動きの抑制、選択肢の一時非表示、中断・再開、お気に入り・メモ・理解度
- 保存：端末内（IndexedDB）、手動エクスポート/インポート（検証・上書き確認）。問題報告（端末内保存と GitHub Issue 用テキスト）
- セキュリティ：秘密情報なし、安全なレンダリング（HTML を直接挿入しない）、インポート検証、依存関係監査（`npm audit` 0）、CSP
- 自動テスト：データ・学習・模試・保存・UI・オフライン・アクセシビリティ・キーボード・堅牢性。CI（GitHub Actions）は教材ビルド→型検査→単体テスト→公開条件ゲート→ビルド→E2E（Chromium/Firefox/WebKit）→Pages デプロイ

## 4. 技術構成（実装済み。作り直さない）

- Vite 6 + React 19 + TypeScript、idb、vite-plugin-pwa、vitest、Playwright、js-yaml、esbuild。ハッシュルーティング・相対 base。`.npmrc` に `legacy-peer-deps=true`

- 検証の仕組み：スキーマ・正答/解説の整合（正解の why だけ「正解です」で始まる）・選択肢記号の参照禁止・計算の独立検算（`verify.value`）・擬似言語の全選択肢実行（`verify.cases`/`verify.result`）・SQL の SQLite 実行（`verify.sql`）・用語の存在（`node tools/missing-terms.mjs`）・文字3-gram の重複/類似検出（0.85 以上はエラー）・`tools/check-release.ts`（公開条件ゲート）。`reviewed:`（ファイルレベル）が無い問題は**未レビューとして非公開**
- 擬似言語：`src/pseudo/`（lexer/parser/interpreter、トレース付き）。`÷` は実数除算で整数型変数への代入時に切捨て（問題文で前提を明示）。IPA 公開問題の記法（繰返し終了、商・余り、平方根、文字列・配列操作 等）対応済み。詳細は `docs/DECISIONS.md`
- ツール：`tools/fix-glossary-dups.py`（統合時の用語重複解消）、`tools/gen-coverage-doc.mjs`、`tools/check-release.ts`（`ENFORCE_H2=1` で H2 条件を強制）
- 用語辞典の規約：名前・別名はリポジトリ全体で一意。別名は真の同義語・略称・表記ゆれのみ（別概念は独立項目）
- YAML の注意：平文スカラーに半角 `: ` を入れない、`NULL/yes/no` は引用符、`[[` は辞典リンク記法

3. 全完了後に**独立レビュー波**：書いた担当とは別のエージェントが、解答を伏せて解き直し、正答の一意性・誤答の確実な誤り・解説の事実・再計算・シラバス適合（`scope` が妥当か）・重複・難易度分類を確認し、問題があれば修正または `status: rejected`、確認済みファイルに `reviewed: { at, method }` を付ける（法令・規格・プロトコルは一次情報で確認）。第二次レビューの記録形式は `docs/REVIEW2_LOG_*.md` を参照
4. 重複検査（既存と新規の横断）、難易度分布の確認（追加の応用+高難度 ≥70%、基礎 ≤10%）、科目A/B・分野別の集計を `hard-batch.json` で確認。不足分は追加執筆
5. 統合 → `ENFORCE_H2=1 npm run check:release` が全通過 → `.github/workflows/deploy.yml` のゲート step に `ENFORCE_H2: '1'` を設定 → 単体・E2E（全ブラウザ）・ビルド → push → GitHub Actions 成功と公開サイトの問題数（manifest）を確認 → 公開環境で高難度特訓・オフライン再読み込みをブラウザで確認
6. 文書を更新（`docs/PROGRESS.md`、`docs/CONTINUATION.md`、`docs/QUALITY_REPORT.md`、`docs/CONTENT_COVERAGE.md`、`docs/DECISIONS.md`）し、最終報告（6.1 の項目）を日本語で出す

## 7. 既知の注意点

- 利用上限（セッション上限）に当たるとサブエージェントが途中停止する。コミット済みの作業は残る。再開は新しいエージェントに続きを指示する
- Playwright はポート 4178 を使う。サブエージェントが同時に使っていると衝突するので、設定のコピーでポートを変えて実行する
- `÷` の扱いなど IPA 仕様が未定義の挙動は、問題文に前提を明記する
- ビルドの重複検出は `firstNumber`（選択肢の先頭の数値）で `verify.value` の一意性を見るため、選択肢が同じ数値で始まらないようにする（例：「0.4倍」と「0.40秒」）
- 並行ワークツリーが古い基底のことがある。作業の最初に開発ブランチをマージする
- 法令・規格は改正が多い。確信のない細部（金額・日数・施行日）に依存しない
- ユーザーの確認が必要な作業（実機確認など）は、依頼文を添えて報告する
