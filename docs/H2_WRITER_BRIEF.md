## 1. 目的と「高難度」の定義

高難度とは次のことであり、それ以外の方法で難しくしてはいけない。

- シラバス内の**複数の概念を組み合わせる**（例：ネットワークとセキュリティ、DBとトランザクション、CPU性能と処理時間、構成と可用性、アルゴリズムと計算量、PMとコスト評価）
- **複数段階の推論・計算**が必要（途中式を追わないと正解できない）
- 学習した原理を**初見の条件に適用**する（暗記では解けない。ただし解答に必要な条件は問題文に十分示す）
- 誤答選択肢が、**受験者が実際にしやすい誤解・計算ミス**に基づく（明らかに不自然な選択肢、正答が推測できる選択肢は禁止）

禁止事項：シラバス外の知識（シラバスにない数学・製品固有の知識・実装詳細）を要求すること／問題文の不必要な長文化・曖昧化・些末な知識問題で難しく見せること／既存問題の言い換え・数値だけの変更・選択肢の並べ替えによる水増し／部分的に正しい誤答。

「シラバスのキーワードが問題文に出てくる」だけでは範囲内と判定しない。**正解するために必要な知識・技能そのもの**がシラバス（Ver.9.2）の範囲に含まれることを `scope` に書いて確認する。擬似言語は IPA「試験で使用する情報技術に関する用語・プログラム言語など」別紙2の範囲。

## 2. 難易度配分（担当問題の合計に対して）

| diff | 区分 | 割合 |
| --- | --- | --- |
| 1 | 基礎 | 5% 以下 |
| 2 | 標準 | 約 20% |
| 3 | 応用 | 約 40% |
| 4 | 高難度 | 約 35% |

diff 4 の目安：3段階以上の推論、または2つ以上の論点の統合が必要で、実力のある学習者が初見で間違えうる。

## 3. 各問題の必須項目（ビルドが検証。満たさないとエラー）

ファイル先頭に `batch: H2`（ファイルレベル）。各問題に：

- `scope`：出題範囲の根拠。対応するシラバス項目名と、解答に必要な知識が範囲内である理由（20字以上）
- `prereq`：必要な前提知識（10字以上）
- `hard`（diff≥3）：難易度を高くしている要素（10字以上）
- `exp`：120字以上。**正解の理由・解答までの考え方**、計算は**途中式**、プログラムは**変数・配列の推移表**（`| 表 |`）
- `why`：選択肢ごとに20字以上。誤答は「どういう誤解／計算ミスでその選択肢に至るか」と「なぜ誤りか」を具体的に。正解の why は「正解です。」で始める
- `know`：30字以上。関連するシラバス知識と**間違えやすいポイント**
- `terms`：1つ以上（辞典にある用語名・別名。新規は `content/glossary/h2-<担当キー>.yaml` に追加。名前・別名はリポジトリ全体で一意）

規約：選択肢記号（ア〜エ）を exp/why/know で参照しない（選択肢はシャッフルされる）。平文の YAML スカラーに半角の `: ` を含めない（引用符かブロックスカラー）。`NULL`/`yes`/`no` などは引用符。表は `| 列 |`、コードは ``` で囲む。

## 4. 独立した正答検証（省略禁止）

「問題を作った推論」と同じ推論だけで確認したものを検証済みとしない。

1. 数値で答える問題：`verify.value` に**別個に書いた JS の式**（答えを直接書かない）。式で表せない場合のみ `verify.manual` に独立した全計算を記録
2. SQL：`verify.sql`（SQLite で全選択肢または結果を実行）
3. プログラム（擬似言語）：`verify.cases`（全選択肢を空欄に当てはめて実行し、正解のみが全テストケースを満たす）または `verify.result`。`src/pseudo/parser.ts`、`tests/unit/pseudo.test.ts`、`docs/DECISIONS.md` で対応構文と意味を確認。÷ の扱いなど仕様が決まっていない前提は問題文に明記する。シミュレーター用に `sim: { entry, args }`（小さい引数）を付ける
4. 知識問題：書いた後に**解答を伏せて解き直し**、各誤答が確実に誤りかを確認。標準・法令・プロトコルの事実で確信がないものは WebSearch/WebFetch で一次情報を確認し、確認できなければ使わない

## 5. 重複防止

既存の同分野の問題ファイルを grep し、同じ出題意図・同じ解法の問題を作らない（ビルドは文字3-gramで 0.85 以上をエラー、0.7 以上を警告）。数値だけ違う問題、言い換えは重複とみなす。担当内でも出題意図・推論の型を変える。

## 7. 科目B（擬似言語）の追加要領

- 実際の科目B（問1〜16 型）に近い**複数段階の読解問題**：長めのプログラム、空欄補充、実行結果・処理回数・戻り値、誤りの発見と修正、アルゴリズムの目的の理解
- 配列は 1 始まり。多空欄は `fills` で 6〜8 択（ア〜ク）にしてよい。説明は問題文に精密に書く（関数の仕様、入出力、前提）
- 問題の少なくとも 60% に `sim` を付ける。解説には必ず変数・配列の推移表
- 科目B セキュリティ（B-SEC）：企業の事例を表・ログで示し、状況から最も適切な対応・原因・対策を選ばせる（4〜6択）。事実に基づく一般的で確実な内容に限る
